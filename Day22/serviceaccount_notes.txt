In Kubernetes, a ServiceAccount is an identity used by Pods to authenticate with the Kubernetes API Server.

    Think of it like this:

NOTE:
    User Account → Used by humans (kubectl)  ( kowsik is user account where we have created and issued certificate)
    Service Account → Used by applications/pods

    Why do we need it?

        Imagine a pod wants to:

            Read pods
            List services
            Create configmaps

    The pod must identify itself to Kubernetes. That's where a ServiceAccount comes in.

    Example

    Create a ServiceAccount:
        kubectl create sa pod-reader-sa 

        verify --> kubectl get sa 

    Now we need to aa=ttach serviceaccount in a pod ---. for that we can give in spec while creating pod: ServiceAccountName: pod-reader-sa

===========================================================================================================================

ServiceAccount + roleBinding  --> important 

but here we are using User + rolebinding 

eg SA :

    kubectl create sa app-sa
 
    kubectl create rolebinding app-binding \
    --role=pod-reader \
    --serviceaccount=default:app-sa

eg User:

    kubectl create rolebinding kowsik-binding \
    --role=pod-reader \
    --user=kowsik
